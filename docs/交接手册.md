## 1. 这个项目是什么

「德育分自动化系统」：班级德育分记录 + 周纪实表/月度总表一键生成（Excel）+ 寝室星级打分 + AI 对接。Windows 单机 Tkinter 应用，v1.7.0 起带完整安装包与 GitHub 热更新。

三大组成：

| 组成 | 位置 | 说明 |
|---|---|---|
| 主程序 | `软件说明/德育分自动化系统.py`（约 3400 行单文件） | 全部业务逻辑，类 `MoralScoreApp` |
| MCP 服务 | `AI对接/mcp_server.py`（约 1080 行，纯 stdlib + openpyxl） | 让 AI 客户端通过对话写入加减分；与主程序靠 `_ai_bridge/` 文件队列通信 |
| 安装与更新 | `installer/`、`src/`、`tools/` | 双路线安装器 + 更新器 + 全套构建脚本 |

## 4. 源码双副本制度（重要）

- **开发副本**（改这里）：`自动化项目（开发测试）\德育分自动化系统正式版\`
- **发布副本**（用户在用）：`德育分自动化系统\软件说明\德育分自动化系统.py`
- 流程：改开发副本 → 回归全绿 → `cp` 同步到发布副本 → `sha256sum` 两边必须一致。
- 用户真实数据目录（`2026年X月\`、`名单模板.xlsx`、`deepseek_config.json`、`_ai_bridge\`）**任何操作都不许写**。

## 5. 日常开发流

```bash
# 改完代码：
$PY -m py_compile 软件说明/德育分自动化系统.py
$PY -X utf8 ../_ui-work/verify_ai_list.py && …fuzzy && …dorm_ai      # 既有回归
$PY -X utf8 tools/test_roster_write.py && …test_updater && …test_blank_run   # 新增测试
```

三套既有回归的原理值得知道：它们用 `importlib` 把主程序当模块加载、`MoralScoreApp._base_dir` 打补丁指向真实数据目录**只读**，再驱动真实 Tkinter 界面模拟 AI 写入/驳回/撤回。所以主程序的函数签名与 `_base_dir` 行为不能随意改。

## 6. 构建链（发新版）

完整命令与顺序见《更新手册.md》§2.3。要点：

1. 主程序 spec 在 `软件说明/`，但构建时把 py/spec/tkwebui 拷到独立临时目录再打，避免污染仓库工作区。
2. `mcp_server.exe`（38.7 MB onefile）、`update.exe`（8.3 MB onefile）由 `src/` 下两个独立 spec 打。
3. `make_payload.py` 只做**白名单复制**：真实数据、API Key、锁文件即使混进构建目录也进不了分发包（有禁入清单自检兜底）。
4. `make_update_zip.py x.y.z` 打热更新包并自动回填 `version.json` 的 sha256/size/url。
5. 安装器：Inno（`ISCC setup.iss`）为发布首选；自写安装器是后备与自定义入口。
6. 空白模板是安装包的一部分：改了模板结构，必须重跑 `make_blank_template.py` + 自检。

## 8. 更新体系速记

- 客户端契约只有一个文件：仓库根 `version.json`。客户端顺序试 manifest → mirror → jsDelivr → GitHub API，各 6 秒超时，全挂就静默（手动检查才提示）。
- 更新包 zip 内部结构 = 安装目录结构；`update.exe --job update.json` 干活：等主程序退出（30s 超时强杀）→ sha256 → 解压 `.update-tmp` → 备份 `.backup\<旧版本>\` → 替换 → 失败回滚 → 写 `安装信息.json` → 重启。
- **用户数据白名单**（`update.py: is_protected`，改这里要极度谨慎）：名单模板.xlsx、更新配置.json、安装信息.json、deepseek_config.json、*.log、`20??年X月\`、`_ai_bridge\`、名单模板.自动备份-*.xlsx。
- 更新器自己也要能被更新：启动时先把自己搬到 `%TEMP%\deyufen-update\` 再执行（`--relocated`）。
- 单测 `tools/test_updater.py` 用假包覆盖 A–E 五个场景，改动 update.py 后必跑。

## 9. MCP 体系速记

- 传输：stdio JSON-RPC（每行一条）；主程序每 2 秒扫 `_ai_bridge/inbox/*.json`，心跳写 `state.json`（含 version/year/month/week/class_name/base_dir）。
- 冻结 exe 后 BASE_DIR 改用 `sys.executable` 定位（`AI对接/mcp_server.py:24`），exe 必须放在 `<安装目录>\AI对接\`。
- 用户挪了安装目录 → 软件内「重新生成 MCP 配置」一键修复。

## 10. 隐私与安全红线（违反就是事故）

1. 真实数据目录只读（名单、月度分数、API Key、AI 队列）。
2. 分发包禁入：deepseek_config.json、`2026年X月\`、`_ai_bridge\`、`~$*.xlsx`、演示视频、旧 zip/pptx/html、真实名单模板。`make_payload.py` 有自检，但别依赖它兜底。
3. `*.zip` 安装包不进 git（用 Releases）；`.gitignore` 已配好，新产物类型记得补。
4. 仓库公开前必须清历史（名单模板 + API Key，步骤见更新手册 §三）；公开后旧 Key 一律吊销轮换。
5. 不动用户注册表的安全项（SmartScreen/Defender），文档里教用户点「仍要运行」即可。
