## 4. 版本号制度（1.9.4.0 的教训）

四处必须一致，**每处逐一 grep 复核**（不要批量替换后想当然）：

```bash
grep -n "APP_VERSION = " 软件说明/德育分自动化系统.py      # ① 主程序 :31
grep -n "MyAppVersion" installer/setup.iss                # ② Inno
grep -n "APP_VERSION = " installer/installer.py           # ③ 自写安装器
grep -n "安装程序-1.9" installer/installer.spec            # ④ 自写安装器 spec 的 exe 名
```

v1.9.4.0 事故：批量替换漏了①，装出来的程序功能全对但自报 1.9.3.0，靠用户截图才发现。
`vtuple()` 支持四位比较（`1.8.3.1 > 1.8.3`），`src/update.py` 的兜底正则同步支持四位。

## 8. 业务规则速记（改动前先读，都是用户拍板过的）

- **寝室检查按次数计分**：同寝室一周期内检查几次算几次（两次五星=成员各+2，明细「周五星寝室×2」）；`dorm_inspections` 累计，`apply_dorm_scores` 求和写入；**应用后清零**并转黑（`dorm_applied`），新结果到达再变青。多次净 0 也写 0 分记录（可追溯）。
- **寝室状态三色**：寝室号颜色 = 青(已报)/红(未发)/黑(已应用)。无文字标。
- **寝室号是文本**，带楼栋（柳412…柳422、梅420/412）；学校 App 路径「…柳园-柳园420-3号床」→ 园区首字+房号 → 柳420（映射规范写在 AI 设定文档）。任何地方不得假设寝室号是数字。
- **AI 寝室流程**：检查结果默认走 `set_dorm_stars` 设滑块（AI 设的寝室号青色），用户核对后点「应用打分」；只有用户明确说"直接记分"才 `add_records` 逐人写。
- **一图两结果只看第一条**（写进 AI 设定文档铁律）。
- **完整名单模板导入 = 整文件 1:1 替换**（保留周表配对/寝室顺序/签字栏）；四列名单才解析重建。
- **名单入口**：拖入窗口（全窗口递归注册）或 设置→添加模板；周表工具栏只有 查加分标准/撤回/重做。
- 用户数据白名单（绝不覆盖/删除）：名单模板.xlsx、更新配置.json、安装信息.json、deepseek_config.json、`20??年X月\`、`_ai_bridge\`、`*.log`、名单模板.自动备份-*.xlsx。两处实现必须同步改：`src/update.py:is_protected` 与 `installer/installer.py` 的 KEEP_*。

## 9. 更新 / MCP 体系速记

- 更新：客户端拉 version.json（manifest→mirror→jsDelivr→GitHub API，各 6s）→ 下载校验 → `update.exe --job`：等退出→备份 `.backup\<旧版>\`→替换（`_internal` 整目录）→失败回滚→重启。断电残留启动时自恢复。
- raw/jsDelivr 有 CDN 缓存（最长 ~12h），发版后旧客户端晚点收到提示属正常；`check_manifest.py` 全绿即可发。
- MCP：stdio JSON-RPC；主程序 2s 轮询 `_ai_bridge/inbox/*.json`。批次两种：普通 records、`type: "dorm_stars"`（`_apply_ai_dorm_stars` 处理）。exe 冻结后 BASE_DIR 用 `sys.executable` 定位。
- GitHub 上传注意：**Release 资产名必须 ASCII**（API 会剥中文名）；本机网络对 `uploads.github.com` 时常抖动，curl 带 `--ssl-no-revoke` + 重试即可。
