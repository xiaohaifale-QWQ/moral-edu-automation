# 更新手册

> 面向两类读者：**使用者**（怎么把软件更到新版本）与**维护者**（怎么发布新版本）。
> 当前版本 v1.7.0（2026-10-24）。

---

## 一、使用者：软件怎么更新

### 1.1 正常途径：软件内「检查更新」

- 侧边栏底部有版本号和「检查更新」按钮；平时软件启动 3 秒后也会**静默**检查一次（每 24 小时最多一次，有新版本才弹窗，不打扰）。
- 弹窗里会显示新版本号、更新说明，选 **立即更新 / 稍后 / 跳过此版本**。
- 点「立即更新」后：下载（带进度与 sha256 校验）→ 程序自动退出 → 更新器替换文件 → **自动重启**，全程不用动手。
- 有未保存的录入时会拒绝更新，先点「生成周表」保存再更。

**你的数据绝对安全**：`名单模板.xlsx`、`20XX年X月\` 数据文件夹、`更新配置.json` 在任何安装/更新/卸载中都不会被覆盖或删除。

### 1.2 国内网络打不开 GitHub

「检查更新」提示网络不可用时，按顺序试：

1. 侧边栏「更新设置」→ 把**镜像地址**填成加速地址，例如：
   `https://ghfast.top/https://raw.githubusercontent.com/xiaohaifale-QWQ/moral-edu-automation/main/version.json`
   （ghfast.top、gh-proxy.com 等前缀加速站时效不定，失效就换一个）
2. 或直接到 [Releases 页面](https://github.com/xiaohaifale-QWQ/moral-edu-automation/releases) 手动下载：
   - 下载 `deyufen-x.x.x-win64.zip` → 解压覆盖到安装目录（**别删名单模板.xlsx**）；
   - 或下载最新的 `德育分自动化系统-安装程序-x.x.x.exe` 直接重装（设置和名单都保留）。

### 1.3 常见问题

| 现象 | 处理 |
|---|---|
| 首次运行弹「Windows 已保护你的电脑」 | 点 **更多信息 → 仍要运行**。程序没买代码签名证书，正常现象，不是病毒 |
| 下载中途失败 | 直接重试；半截文件不会残留（临时文件自动清理） |
| 提示「sha256 校验失败」 | 下载包损坏或源被篡改，程序已拒绝安装；换镜像重下 |
| 更新时断电/被强关 | 下次打开更新器会自动从 `.backup` 恢复原版本再重新更新，不会坏目录 |
| 更新后想退回旧版 | 安装目录 `.backup\<旧版本>\` 里有完整旧文件，拷回即可 |
| 更新器日志 | `%LOCALAPPDATA%\德育分自动化系统\update.log`（排查用） |

## 二、维护者：发布新版本 SOP

### 2.0 前提（一次性）

- 仓库必须对**使用者匿名可读**（公开）。当前为私有，见 §2.4 的公开化步骤。
- 本机工具：Python 3.12（`C:\Users\32570\AppData\Local\Programs\Python\Python312`，含 openpyxl 3.1.5 / pandas / PyInstaller 6.20）、Inno Setup 6.7.3（`%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe`）、Git。

### 2.1 改版本号（三处必须一致）

1. 主程序 `软件说明\德育分自动化系统.py` 顶部 `APP_VERSION = "x.y.z"`
2. `installer\setup.iss` 的 `#define MyAppVersion "x.y.z"`
3. `version.json` 的 `version`（第 2.3 步脚本会自动回填，可不管）

规则：功能/数据结构变更 → 次版本 +1；只修 bug → 修订 +1。

### 2.2 自检（全绿才继续）

### 2.3 构建链（按顺序）

```bash

"$PY" -m PyInstaller --clean --noconfirm --distpath ../_build_pkg/installer/dist --workpath ../_build_pkg/installer/build installer.spec
```

### 2.4 发布

```bash
git add -A && git commit -m "release: vx.y.z" && git push origin main
```

GitHub → Releases → **Draft a new release** → tag 填 `vx.y.z` → 上传
`release/deyufen-x.y.z-win64.zip` 和安装程序 exe → 填更新说明（与 version.json 的 notes 一致）→ **Publish**。

最后复核（应输出「清单与资产校验通过」）：

```bash
"$PY" -X utf8 tools/check_manifest.py
```

可选：推 tag（`git tag vx.y.z && git push origin vx.y.z`）会触发 `.github/workflows/release.yml` 在 GitHub 上自动构建一个源码编译版 zip 附到 Release，仅作透明性参考，**正式分发用本地打的包**。

### 2.5 发版检查表

- [ ] 三处版本号一致
- [ ] 2.2 自检全绿
- [ ] 更新包已上传 Release 且 Publish
- [ ] `check_manifest.py` 通过（raw + jsDelivr + 资产哈希）
- [ ] 装一次旧版 → 软件内「检查更新」→ 走完一次真更新（终极验证）

### 2.6 min_supported 与强制更新

`version.json` 里 `min_supported` 低于它的老客户端会弹**不可取消**的更新提示。
数据结构不兼容的版本务必抬高它。`mandatory: true` 目前未启用，保留字段。

## 三、仓库可见性（当前为私有，热更新前置条件）

「检查更新」依赖**匿名可读**的 `version.json`（raw.githubusercontent / jsDelivr）和**匿名可下载**的 Release 资产。**仓库私有 = 所有用户的检查更新都失效**（表现为「网络不可用」）。

公开前**必须**先清历史——旧提交里有含 47 名真实学生的 `名单模板.xlsx` 和含 API Key 的 `deepseek_config.json`：

```bash
pip install git-filter-repo
cd 自动化项目（开发测试）/德育分自动化系统正式版
git filter-repo --invert-paths --path 名单模板.xlsx --path deepseek_config.json --path 识别记录日志.txt --force
git remote add origin https://github.com/xiaohaifale-QWQ/moral-edu-automation.git
git push origin main --force
```

然后在 GitHub 设置里把仓库改为 Public。**若曾公开过， DeepSeek API Key 视为已泄露，先去 DeepSeek 平台吊销换新**（新 key 只写在用户本地的 `deepseek_config.json`，该文件已永久不入库）。

若决定保持私有：热更新不可用，改用「 Releases 手动下载」模式告知使用者，或在「更新设置」里指向自己搭的静态文件源（manifest_url 指向任意可匿名访问的 version.json 即可，无需 GitHub）。
